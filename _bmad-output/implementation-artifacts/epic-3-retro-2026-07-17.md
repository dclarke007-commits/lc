## 2. What Went Well

- **Adversarial multi-layer review earned its keep — every story.** Blind Hunter + Edge Case Hunter + Acceptance Auditor (plus a dedicated security pass) caught *real* HIGH/MED defects **before merge**, not after: the 3-1 replay vuln, the 3-4 TOCTOU attribution race, and the 3-6 nonce-collapse + no-show suppressor. Zero vulns slipped.
- **Derive-on-read (AD-7) purity held across the epic.** Lapse detection reused the *same* cadence arithmetic (`CADENCE_INTERVAL_DAYS`) as 3.3 rebooking, so lapse and rebooking agree on one calendar. No stored `gone-cold` flag, no cron, no migration — mutate the rows and the next read reflects it. The 16→17 pure unit tests prove recompute-on-mutation.
- **Shared dispatch seam (Story 2.3 `recordDispatch`) absorbed both nudge and win-back** with no new compose/template/log path (AD-5). Win-back was genuinely a thin consumer.
- **Verify discipline caught what "green" subagents missed.** Independently re-running `tsc` + full suite surfaced the 2 nonce-format test breakages the P2 change introduced — they'd have been silently shipped otherwise.

## 3. What Was Hard / Challenges

- **Shared-predicate reuse drift.** `capacity.consumesSlot` (`booked|completed|no-show`) was reused as the `goneCold` future-booking suppressor — but lapse's "on the books" means **`booked` only**. A today/future `no-show` (the lapse signal itself) would have *suppressed* the lapse. The capacity abstraction and the lapse abstraction diverged silently because the predicate looked reusable. (Fixed P3.)
- **Idempotency nonce keying is subtle without a natural anchor.** Rebooking keys per `jobId`; win-back has no anchor job, so it was keyed per-`clientId` — which collapsed *every future win-back into one lifetime log row*, under-counting nudge-fatigue. The fix keys per **cold-spell** (`winback:<clientId>:<expectedNextDate>`). (Fixed P2.)
- **Fail-pattern asymmetry within one surface.** `getWinBackDraft` was fail-closed (AD-8), but `listOwnerClientsWithLapse` — rendered on every `/clients` load — was not, so a corrupt `settings.timezone` would 500 the whole page. (Fixed P1, fail-open to unannotated list.)

## 4. Key Insights / Lessons

1. **A predicate that "looks reusable" is not automatically correct for a new consumer.** Reusing `consumesSlot` for lapse was wrong because capacity-consuming ≠ lapse-on-file. Shared predicates need an explicit per-consumer intent check, and a named predicate at the point of reuse.
2. **Idempotency nonces must key on the *event instance*, not the entity.** No natural anchor → invent a spell discriminator (here, `expectedNextDate`), don't fall back to the bare entity id.
3. **Apply the fail pattern uniformly across all read paths of a surface**, not just the one you were thinking about. One unguarded read takes the page down.
4. **Independent verification of subagent "green" is non-negotiable** — it has now caught real issues on multiple stories.
