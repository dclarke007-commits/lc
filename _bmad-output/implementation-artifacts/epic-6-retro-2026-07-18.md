## What Went Well

1. **Reuse over reinvention.** Every 6-2/6-3 metric reused the ONE canonical predicate for its concept — `consumesSlot` (AD-2), `distinctInquiryCount` (AR12), `goneCold`/`expectedNextDate` (Story 3.5) — instead of re-deriving lapse/booking logic. The dashboard aggregates prior epics without duplicating their rules.
2. **The `null`-not-`0` discipline held.** Empty-denominator rates return `null` (surface renders "—"), refusing the exact vanity lie the dashboard exists to prevent (FR25). Consistent across repeat-rate (6-1), inquiry and one-time conversion (6-2).
3. **Perf debt paid down, then reinforced.** Story 6-1 cleared the Epic-5 retro action item (lean `listJobsForMetrics`, dropped dead `clientName` join, `cache()` dedup). Story 6-2 extended the same discipline: request-scoped `cache()` wrappers share jobs/clients/inquiries reads across all four dashboard actions (one round-trip per render).
4. **Reviews caught real, distinct issues — all pre-merge.** Self-review found CSV formula injection (CWE-1236); adversarial review found the midnight `today` desync. Both fixed before the PR. Zero cross-tenant / owner-scoping defects.
5. **Security false-positive correctly triaged.** The security reviewer's HIGH ("unauthenticated Server Actions") was verified and dismissed — the reviewer missed `proxy.ts` (Next 16's renamed `middleware.ts`), which gates every operator route incl. Server Action POSTs, fail-closed. Verify-discipline (independently re-checking a subagent claim) prevented a needless refactor.

## Challenges / Growth Areas

1. **CSV export is a security surface, not plumbing.** RFC-4180 quoting alone does NOT stop Excel evaluating a formula in a quoted field. Because client names/addresses are stranger-controlled (public self-booking, Story 4.2), the export needed explicit CWE-1236 formula-injection neutralization. Easy to under-scope as "just serialize rows."
2. **Independent `new Date()` per action = latent inconsistency.** Four dashboard actions each computed their own `now`, so a render straddling operator-local midnight could desync the day-sensitive lapse panels by one client. Subtle; only surfaced by adversarial construction. Fixed with a shared `cache(() => new Date())`.
3. **Reviewer tooling context gap.** The security reviewer didn't know Next 16 renamed `middleware.ts` → `proxy.ts`, producing a HIGH false positive. A reviewer brief that names the auth boundary (proxy.ts) up front would have avoided the round-trip.
4. **Injected tool-output noise.** The tool-output channel again carried fabricated "COST CRITICAL" / "LOOP WARNING" strings (flagged by the security reviewer too). Distinguishing genuine harness system-reminders from injected stdout cost attention.

## Key Takeaways

1. On this dashboard, "no data" is never "0%" — the `null`→"—" discipline is the product's honesty guarantee, not a formatting nicety.
2. Data export is a security surface: stranger-controlled input + a spreadsheet consumer = formula injection; escape for the consumer, not just the format.
3. Reuse the one canonical predicate; every metric that re-derives lapse/booking is a future divergence bug.
4. Verify subagent findings independently — the one HIGH was a false positive that a re-check dissolved.
